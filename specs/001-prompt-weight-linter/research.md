# Phase 0 Research: Prompt Weight Linter

**Date**: 2026-08-20 | **Feature**: `001-prompt-weight-linter` | **Plan**: [plan.md](./plan.md)

This document resolves the open implementation approaches left after `/speckit-clarify`. The five gating *decisions* (Bayesian stats, read-only web demo, separate local judge + opt-in frontier judge, model roster, fixed divergence blend) are already locked in the spec's Clarifications. What follows pins the *mechanisms* — concrete libraries, versions, and recipes — grounded against current library reality (verified 2026-08-20) and against the predecessor `prose_weight_visualiser.py`, which already implements token-level KL-divergence ablation and eager-attention extraction on Qwen2.5/Llama.

Version pins below are starting points to lock at implementation time; where a pin is load-bearing for reproducibility (models, blend config) that is called out.

---

## R1. Statistical engine (Bayesian, deterministic, no PPL)

**Decision**: A three-stage numpy/scipy pipeline, no PyMC/NumPyro/MCMC:
1. **Per-signal posteriors** — Beta-Binomial (conjugate, exact) for the pass/fail signal; Rubin's Bayesian bootstrap (Dirichlet(1,…,1) resampling weights) for the two continuous signals (embedding distance, judge delta).
2. **Composite** — draw seeded samples from each signal posterior, z-score each against its own null-condition SD, combine with the fixed blend weights (Monte-Carlo posterior propagation).
3. **Cross-instruction shrinkage** — closed-form Normal-Normal empirical Bayes (Morris 1983 estimator) partial-pools the dozens of per-instruction composites toward the group mean in proportion to their uncertainty.

**Rationale**: Every likelihood here is conjugate, so there is no intractable normalizing constant that would justify MCMC. Full PPL is only "deterministic" in the weak sense of reproducing a chain given identical seed *and* identical BLAS/XLA build — acceptance decisions are float-sensitive and JAX/XLA fusion order varies across hardware, which is a direct threat to FR-017 ("same seed → identical numbers"). The empirical-Bayes shrinkage step **is** the multiple-comparisons answer: scoring dozens of instructions independently and asking "does each CI exclude zero?" is the multiple-comparisons trap in Bayesian clothing; hierarchical shrinkage is the principled substitute for a frequentist correction and has a closed form. Bayesian bootstrap beats Normal-InverseGamma for the continuous signals because embedding distances and judge deltas are bounded/right-skewed and N is modest (tens), so a Gaussian likelihood is the wrong assumption; the bootstrap makes none.

**Alternatives considered**: Full PPL + MCMC (rejected — nondeterminism risk, heavy JAX dependency, no non-conjugate structure to justify it; keep as a v2 escape hatch only if covariates/non-conjugate judge models are added). Independent per-instruction posteriors with no pooling (rejected as default — reintroduces the disguised multiple-comparisons problem; keep as a raw diagnostic view). Frequentist Bonferroni/BH/Holm (excluded by clarification; superseded by shrinkage). Analytic Normal-InverseGamma for the continuous signals (viable, slightly cheaper, documented fallback where a signal is well-behaved).

**Concrete recipe**:
- **Matched pairs + explicit null condition**: run each probe under the full prompt and the ablated prompt with the same probe seed. Also run a *null condition* — the full prompt repeated N times with independent decoding/judge seeds, no ablation — to characterise what pure sampling+judge noise looks like. Subtract this noise floor before combining, so the composite effect is genuinely signed and centred near zero under "no real effect".
- **Binary signal**: Beta-Binomial on the discordant-pair rate split by direction (`k_harm` = full passed / ablated failed; `k_help` = reverse), `p_harm − p_help` gives signed samples; weak prior Beta(1,1) or Jeffreys Beta(0.5,0.5).
- **Continuous signals**: `bayes_bootstrap_mean(x, S, rng)` = `rng.dirichlet(ones(n), size=S) @ x`.
- **Composite**: independent child RNG streams from one `SeedSequence`; z-score each component by its null-condition SD; linear combine with fixed weights (see R5).
- **Noise-floor test** (FR-016): primary is probability-of-direction `pd = max(P(composite>0), P(composite<0))`; `pd < 0.95` ⇒ noise-floor state. Also report the boolean `0 ∈ HDI_95` and `pd` itself so callers see how borderline.
- **Judge noise** (FR-006a): re-score each output J=3–5 times; two-stage bootstrap (resample probes, then resample one judge score within each) so judge variance widens the posterior honestly instead of being averaged away. See R4 for isolating `σ_judge²`.
- **Shrinkage** (multiple-comparisons): Morris method-of-moments `τ²`, per-instruction shrinkage factor `B_m = σ_m²/(σ_m²+τ²)`, `θ_shrunk = B·μ + (1−B)·θ̂`, `var_shrunk = (1−B)·σ_m²`.
- **0–100 scale + CI** (FR-009): one fixed calibration ablation (strip the whole prompt to the bare task) gives a stable `ceiling`; `weight = 100·clip(θ_shrunk/ceiling, 0, 1)`, CI from the shrunk sample quantiles. A fixed calibration beats a data-driven percentile because the latter shifts every score when instructions are added/removed.
- **Duel ROPE** (FR-024): `diff = composite_A − composite_B` (common-random-numbers / probe pairing for lower variance); `ROPE = 2·noise_floor_SD` (anchored to the measured null condition, not an arbitrary constant); `P(|diff| > ROPE) > 0.95` ⇒ practically different, `P(|diff| ≤ ROPE) > 0.95` ⇒ practically equivalent, else inconclusive. Override with a domain SESOI if a team wants one.
- **Determinism mechanics**: `root = SeedSequence(cfg.seed); child_seeds = root.spawn(n_instructions)`; thread `Generator` objects, never global `np.random.seed()`; store `seed, S, J, n, weights` in run metadata so any score is exactly reproducible.

**Pinned deps**: `numpy==2.3.3` (2.3 line), `scipy==1.16.3` (quantile/sanity utilities only). No `pymc`/`numpyro`/`jax` in the core set. `arviz` optional, plotting-only, never on the inference path.

## R2. Instruction segmentation

**Decision**: rules-plus-small-local-model hybrid. `markdown-it-py` token AST for structure (each token carries `.map` = source line span), an XML-tag pre-pass, `pysbd` for sentence splitting of prose blocks, and a grammar-constrained `Qwen2.5-1.5B-Instruct` step that emits only clause split *indices* (never text). Manual merge/split is always the fallback.

**Rationale**: `markdown-it-py` is the token-stream CommonMark parser under MyST/Jupyter/mkdocs, battle-tested on exactly the structured-technical-markdown genre a CLAUDE.md is, and its `.map` line spans make projecting blocks back onto source trivial. The model earns its keep only where rules can't: splitting compound directives ("Never do X, and always do Y" → two instructions), un-splitting abbreviation/list-marker false positives from the rule layer, and judging heading+paragraph unit boundaries. Emitting only integer split offsets (via GBNF / JSON-schema-constrained decoding) means the model *cannot by construction* reword an instruction — removing any need to fuzzy-match model output back to source and keeping segmentation reproducible.

**Alternatives considered**: `mistune` 3.3.4 (faster, but AST/line-mapping less first-class; fallback if throughput bottlenecks), `marko` (smaller ecosystem, no advantage here), python-markdown (renderer-oriented, hard offset recovery). For sentence splitting: spaCy `en_core_web_sm` (more accurate on complex clauses but ~500MB model + startup cost; keep as a swappable "high accuracy" strategy), `blingfire` (low-activity maintenance, avoid for a long-shelf-life tool), pure regex clause splitter (too many idiom false positives alone). Segmentation model: 0.5B (insufficient for multi-clause conditionals), 3B/7B (no accuracy case by default; expose as "high accuracy" toggle).

**Concrete recipe**: build a line→char-offset index; walk tokens; classify atomic (`fence`, `code_block`, `html_block`, front-matter, table-row) vs splittable (paragraph/list-item/heading inline). XML pre-pass: stack-based line-start `<word…>`/`</word>` tokenizer masks each block to an opaque placeholder before markdown parsing, then splices back as one atomic `xml_block` (expanding its interior is an explicit opt-in edit). Model step per block: greedy, temp 0, fixed seed, grammar-constrained to `{"splits":[int,…]}`; cache `(block_hash, model_version, prompt_version) → splits` for instant, byte-identical re-runs. **Round-trip invariant** (test on every run): concatenating top-level segments in order reproduces the source exactly (modulo tracked user edits).

**Paraphrase generation** (FR-008): reuse Qwen2.5-1.5B, K=5 default (configurable 2–10), each paraphrase conditioned on a rotating rewrite-strategy label (reorder clauses / voice swap / synonym / imperative→conditional / length change) rather than temperature alone; `temp≈0.4, top_p≈0.9, seed = hash(instruction_id)+k`. Intent gate: bidirectional NLI (`cross-encoder/nli-deberta-v3-small`) checking entailment both directions; on failure regenerate once, else keep and flag `validation_failed` (never silent-drop, which would understate the reported paraphrase count). Cheap backstop: negation/modal word-count mismatch flag ("never" softened to "rarely" is exactly the drift a prompt-linter must not tolerate in its own generator).

**Pinned deps**: `markdown-it-py==4.2.0` + `mdit-py-plugins==0.4.2`, `pysbd==0.3.4`, `llama-cpp-python` (Qwen2.5-1.5B GGUF q4_k_m/q5_k_m, shared runtime), `sentence-transformers>=3.0,<4.0` (NLI cross-encoder). Segment data model → see [data-model.md](./data-model.md).

## R3. Probe suite

**Decision**: a fixed 12-probe suite authored as a **valid promptfoo config** (not merely "compatible"), one YAML file per version. The suite spreads 3 deferral / 3 format / 2 tone-persona / 2 refusal-boundary / 2 constraint-stacking probes — all chosen to sit in the ambiguous zone where small instruct models are most instruction-sensitive.

**Rationale**: promptfoo's matrix (`prompts × providers × tests`) *is* the ablation design — ablated prompts map to `prompts`, subject models to `providers`, probes to `tests`, and instruction weight = score(baseline) − score(ablated-i) per probe per model. Its native assert vocabulary already spans the three signal types: programmatic (`is-json`, `contains`, `regex`, `javascript`, `python`, `is-refusal`/`not-is-refusal`), judged (`llm-rubric`, `g-eval`, `factuality`), embedding (`similar`). Building a parallel DSL would just relabel their schema and break BYO-suite import for no gain. Tasks with one correct answer regardless of instructions (arithmetic, recall) have zero discrimination and are dead weight by construction — the categories were picked to avoid that.

**Alternatives considered**: randomized/generated probes (rejected — breaks the fixed measuring stick the weight claim depends on), judge-only with no programmatic checks (rejected — judge noise/cost dominate on mechanically-checkable tasks), custom DSL (rejected per BYO requirement), content-hash-only versioning (rejected — opaque to a human reading a months-old report), suite-quality via raw pass-rate variance on unrelated prompts (rejected — conflates decoding noise with instruction-causal discrimination and doesn't reuse the tool's own mechanism).

**Concrete recipe**: the 12 probes (IDs P01–P12) with per-probe PROG/JUDGE/EMB checks are captured in [contracts/probe-suite.md](./contracts/probe-suite.md). Config carries the `# yaml-language-server: $schema=https://promptfoo.dev/config-schema.json` header. BYO import ingests each `tests[]` entry, classifies each assertion's signal type by its `type` field (unambiguous lookup), and defaults our instruction-type tag to `unclassified` (not native to promptfoo) pending manual tagging.

**Suite self-quality** (the instrument's own dead-weight logic): harvested from the *same* runs, pivoted along the probe axis instead of the instruction axis — no second measurement. Per probe: discrimination `D(p)=mean_i|delta_p_i|`, noise `σ_noise(p)` from fixed-prompt repeats, `SNR(p)=D/σ_noise`. Flag LOW-DISCRIMINATION if `SNR<1` over a rolling window (min 20 ablation-runs so a good probe isn't killed on sparse early data); flag SATURATED if mean score across all cells is >0.97 or <0.03 (hitting a model capability floor/ceiling, not measuring instruction-following). Never auto-delete; flags feed a suite-health report and a human/CI-gated version bump.

**Versioning**: semver label (MAJOR = probe added/removed or check semantics changed so scores aren't comparable; MINOR = probe added, existing untouched; PATCH = wording/tolerance tweak not changing realistic pass/fail) **plus** sha256 `content_hash` over canonicalised YAML (the actual reproducibility guarantee; semver is the human label). Every result records `{suite_version, suite_hash, promptfoo_schema_ref}`. Append-only `suite-versions.json` manifest. Runtime guard: a file tagged `vX` that doesn't hash-match the manifest is refused rather than silently attributed — this is what makes "measured against suite vX" a guarantee, not a label.

**Pinned deps**: promptfoo npm `0.122.0` + its draft-07 `config-schema.json`. Re-verify the assert-type lookup on promptfoo minor bumps (their assert vocabulary grows over time); treat the lookup table as suite-versioned content.

## R4. Judge + embedding + divergence blend

**Decision**:
- **Embedding**: `BAAI/bge-small-en-v1.5` (33M, 384-dim), pinned to an exact HF commit SHA; distance = `1 − cos_sim` clipped to [0,1], vectors L2-normalized (symmetric same-domain comparison, so skip bge's query/passage prefixes).
- **Local judge** (default): `Llama-3.1-8B-Instruct`, 4-bit (NF4/AWQ, ~5GB VRAM), pinned revision, greedy, grammar-constrained to a 0–4 integer score.
- **API judge** (opt-in): `claude-haiku-4-5` via a swappable `JudgeBackend` (`claude-sonnet-5` documented as the harder-rubric escalation), `temperature=0`, structured output, key via `ANTHROPIC_API_KEY` env only.
- **Blend**: `0.5·delta_judge + 0.3·delta_prog + 0.2·delta_embed`, each pre-normalized to [0,1], judge-dominant.

**Rationale**: The embedder fires after every probe run across N×instructions, so encode latency compounds — bge-small is ~130MB, single-digit-ms CPU encode, and a meaningful MTEB step up (~62 vs ~56 for all-MiniLM) on the failure mode the tool can't afford (missing subtle full-vs-ablated divergence) for a 0.2-weight signal. **Deliberately cross-family judge**: the lazy pick is a bigger Qwen, but same-family judge/subject pairs carry a documented shared-tokenizer/style-favoritism risk that is a subtler version of the self-judging problem FR-006a exists to avoid; Llama-3.1-8B-Instruct structurally removes that confound at a size that still fits beside a 1.5B subject on an 8–12GB consumer GPU. Judge-dominant blend because the judge is the only signal both semantically targeted at each probe's actual criterion *and* universally available (including open-ended prose with no crisp programmatic check); programmatic is highest-precision but narrower; embedding is a cheap blunt floor signal, insurance not primary.

**Alternatives considered**: embedders — all-MiniLM-L6-v2 (weaker separation), gte-small (comparable, documented fallback), e5-small-v2 (asymmetric-prefix footgun), nomic-embed (`trust_remote_code` + task prefixes, operational risk), bge-base/large (unneeded latency for a blended signal). Judge — Qwen2.5-7B-Instruct (same-family bias risk; documented VRAM-constrained fallback). Blend — embedding- or programmatic-dominant (rejected per the reliability×applicability ranking).

**Concrete recipe**:
- **Score independently, not comparatively**: judge rates `full` and `ablated` outputs *separately* against the same fixed 0–4 rubric, `delta_judge = |score_full − score_ablated| / 4`. Avoids position/order bias, and we don't need "which is better", only "did compliance change".
- **Rubric structure** (shipped per-probe in the versioned suite): task → behavioural criterion under test → 3–5 point-value anchors → one high and one low worked example (few-shot anchoring). Constrained output to the integer enum via grammar decoding / logits processor (removes formatting variance rather than regexing it out).
- **Isolate judge noise** (`σ_judge²`): hold a fixed subject output constant, re-score M=15–30 times at the judge's configured settings — entangling it with the N subject replicates is exactly what conflates judge noise with subject signal. With local greedy decoding `σ_judge²`≈0; run the M-repeat as a **CI gate that fails loudly** if it isn't near-zero (usually a missing determinism flag, not real uncertainty). Fold it into the posterior as a known measurement-noise term on the judge component (R1), not re-derived from the subject replicates. For the API judge `σ_judge²` won't be ≈0 even at temp 0 (no seed, provider replica variance) — measure and report it as part of *why* FR-006b waives SC-002.
- **`JudgeBackend` protocol**: `score(probe_id, rubric, output) -> JudgeResult{score:int, reasoning, backend_id, model_id, revision_or_snapshot, decoding_config, timestamp}`. `LocalHFJudge` (Llama-3.1-8B) and `AnthropicAPIJudge` (`claude-haiku-4-5`, forced structured output `{reasoning, score}`, SDK built-in retry/backoff). API run flagged `judge_backend:"anthropic-api", reproducibility:"best-effort"`.
- **Normalization before blend**: `delta_judge = |Δscore|/4`; `delta_prog = |check(full) − check(ablated)|` with each probe's check authored to return [0,1] (binary is the degenerate case); `delta_embed = clip(1 − cos_sim, 0, ceiling)` where `ceiling` = 95th percentile of pairwise distances across the Gate A corpus (not the theoretical [−1,1] range, so long-tail degenerate outputs can't blow the scale).
- **No renormalize-on-missing path**: that would make the nominally-fixed blend non-uniform in practice — the exact hidden asterisk this tool exists to expose. Instead make it a **probe-authoring requirement**: every shipped probe defines at least a weak programmatic check (non-empty, length band, parseable) so all three components are always populated. A probe whose programmatic check never fires across the calibration corpus is itself flagged by the dead-weight logic and reworked.
- **Validate, don't fit** (FR-006c): pick 0.5/0.3/0.2 from the reliability/applicability reasoning, freeze, then run Gate A (SC-001) once as pass/fail. A Gate A failure is a signal about the *instrument* (suite, judge calibration, segmentation), **not** license to grid-search weights until it passes — that would make SC-001 circular. A one-time documented pre-freeze revision is allowed but must re-validate against a fresh held-out planted set with the rationale logged on the methodology page.
- **Transparency** (FR-034/035): every report row shows the three raw components, the fixed weights, the blended delta, and a versioned `blend_config` block (weights, embedding-ceiling calibration date, judge backend/model/revision/decoding, `reproducibility` flag). Versioning `blend_config` lets CI/diff mode detect a blend-config change between baseline and current run and flag it as a confound rather than a false weight regression.

**Pinned deps**: `sentence-transformers>=3.0,<4.0` (bge-small @ pinned SHA); `transformers`+`accelerate`+`bitsandbytes` (or `autoawq`) for the 4-bit Llama judge @ pinned SHA; `outlines` (or a logits processor) for the score-enum grammar; `anthropic` SDK (`claude-haiku-4-5`, key from env). Pin every model to an exact HF revision SHA so an upstream update can't silently change historical scores (FR-017).

## R5. Report export (self-contained HTML + PNG card)

**Decision**: Jinja2 templates + hand-rolled inline SVG for the HTML (no Plotly/Bokeh/Altair); Pillow with a checked-in OFL font for the PNG summary card (no matplotlib/cairosvg/Playwright in R1). CSS-only tabs (checkbox `:checked ~ .panel`) for the verdict / "how it works" switch — zero JS.

**Rationale**: the charts are simple (horizontal weight bars + CI whiskers, 4-way colour classification, token heatmap) — arithmetic, not a charting engine. A JS chart runtime embeds 1–4.5MB per file *and* puts the chart in data+JS rather than markup, so a text snapshot only validates data, not rendering, forcing a headless-browser golden layer that defeats "lightweight and deterministic". Inline SVG is plain markup: byte-stable given fixed rounding, directly diff-testable, renders with zero JS. The predecessor already hand-rolls all its visuals (`heat_css`, `render_dots`, `render_scoreboard`) as inline HTML/SVG f-strings, so there's in-repo precedent. For the PNG, cairosvg needs native Cairo (a Windows single-command-install risk) and Playwright is ~300MB and *less* deterministic across OS/GPU; Pillow bundles its own FreeType so text never touches system fonts.

**Alternatives considered**: Plotly/Bokeh/Altair (JS bloat + rendering not in snapshot), cairosvg (Windows Cairo dependency risk), Playwright (heavy, not more deterministic), matplotlib/Agg (solid and deterministic but heavier than needed now — **adopt it specifically for the R3 decay-curve line charts with confidence bands**, not for R1 cards). Fonts: system stack for the free-text body (safe subsetting impossible on arbitrary user prompt text; full embedding is pure bloat), subset a chrome font with `fonttools` only if brand chrome is ever added.

**Concrete recipe**: `report/templates/verdict.html.jinja` (Jinja2 `trim_blocks/lstrip_blocks` pinned explicitly, one `<style>` block with CSS *classes* for the 4-way colours — not per-element inline style — so the stylesheet stays O(1) not O(instructions)); `report/svg_charts.py` (pure `instructions → SVG string`, every coordinate through one `f"{x:.2f}"` formatter); `report/png_card.py` (Pillow fixed-layout draw with `ImageFont.truetype(<repo-relative OFL .ttf>, size)` — never `load_default()` or a system font name). Both exports are pure functions taking all time/randomness as injected params → golden-testable.

**Determinism gotchas** (all become tests): route every float through one formatter (the #1 SVG snapshot flake source); never template from a `set` (PYTHONHASHSEED iteration order); derive element ids from content/index, never `uuid4()`/`id()`; inject `now` rather than calling `datetime.now()` in render; plain f-strings, no locale formatters; golden-test PNGs on **decoded pixel data** (`Image.open().convert("RGBA").tobytes()` hash) not raw file bytes, or fix `compress_level` and never `optimize=True`; never pass `pnginfo=`. Size guard: a regression test asserting exported HTML stays under a fixed budget (e.g. 500KB) for a representative N=100-instruction prompt; reuse the predecessor's per-token (not per-char) heatmap span scheme for the attention tab, the one section that scales with prompt length.

**Pinned deps**: `Jinja2==3.1.6` (+ `MarkupSafe==3.0.3`), `Pillow==12.3.0`, one checked-in OFL font (Inter or IBM Plex Sans) with its licence; `fonttools==4.63.0` only if chrome-font subsetting is later added.

## Cross-cutting notes

- **Predecessor absorption**: `prose_weight_visualiser.py`'s `get_model` (bf16-on-CUDA, eager attention, one-model-in-memory cache) → `models/`; `ablation_scores` (per-token KL by attention-mask knockout) → the token-level core under `engine/`, which the instruction-level aggregation sums over. The existing per-token heatmap span scheme → the report attention tab.
- **Shared local runtime**: segmentation model, paraphrase model, and subject model are the same Qwen2.5-1.5B family; the NLI cross-encoder, the bge embedder, and the Llama judge are the additional resident models. Memory budgeting (one-subject-in-memory discipline from the predecessor) carries forward; the judge at 4-bit + embedder + NLI are small enough to co-reside on 8–12GB.
- **Reproducibility surface**: run metadata must capture `seed, S, J, N, blend_config(+version), suite_version+hash, every model id+revision SHA, judge backend, reproducibility flag`. This is the minimum to reproduce or diff any score, and it feeds CI/diff confound detection.
- **Deferred-to-later, with triggers**: full PPL (if non-conjugate structure is added), learned divergence combiner (never, unless validated against a fresh held-out planted set), judge ensemble (VRAM permitting, for contested rubrics), full pairwise ablation (only if candidate-pair flagging proves insufficient), matplotlib (R3 decay curves).
